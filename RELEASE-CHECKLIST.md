# Release and maintenance checklist

- Review current official API, authentication rotation, scopes/plans/quotas, MCP and community alternatives; record source hashes and schema corrections.
- Regenerate from reviewed source; synchronize package/changelog/manifest, full arguments/client docs and CMS source.
- Build, typecheck, test realistic provider behavior and perform real full/read-only SDK discovery.
- Run the shared blueprint gate; inspect the complete rendered README, logo/GIF and expanded FAQs.
- Scan sanitized public history and exact packed artifacts for credentials; never push legacy private refs.
- Inspect npm file list and production-only desktop dependencies/licenses, and record audits separately.
- Publish the default-branch source, wait for CI, push an annotated matching version tag and verify serialized release workflow.
- Verify public npm latest/keywords, repo topics, downloaded desktop hash/manifest and clean artifact discovery.
- Publish the full CMS guide with valid hub taxonomy, exact desktop link and structured FAQ, then read it back and inspect it live.
- Record true live account, desktop GUI and matched task/token evidence; keep unverified outcomes explicit.
- Update programme/catalogue/open work. Follow the site's separate deploy instructions for pending terminal scenes.

Codex-first validation: check current installed CLI help, local stdio registration and private environment forwarding. Measure Claude Code (every tool loaded, tool search, SKILL.md) and Codex (one task over MCP and the CLI, five runs each) against the last npm release, and publish the figures in README section 7. Keep client-specific measurements labelled; never reuse Claude figures as Codex results.
